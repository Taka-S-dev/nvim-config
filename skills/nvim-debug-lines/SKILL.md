# nvim-debug-lines

利用者の Neovim には、デバッグ行を入れて一覧・一括で消す機能がある（`:h cfg-debug-lines`）。
デバッグ行は、行の最後の目印のコメントで見分ける。

- 利用者が入れた行: `/* DBG:グループ #3 */`（グループと番号は無いこともある）
- AI が入れた行: `/* DBG-AI:グループ #7 */`（Neovim で別の色になり、一覧に `AI` と出る）

番号はプロジェクトの中の通し番号で、`add` が自動で付ける（何行かのかたまりは同じ番号）。
出力の `[DBG-AI 7 グループ]` はソースにも同じ文字で書かれるので、ログのその文字で grep すれば、
行がずれていても入れた行に戻れる。利用者は `<leader>dj` でログの行から飛べる。

**デバッグ行は、必ず下のコマンドで入れて消す。** ファイルを書き換える道具（エディタの機能、パッチ、シェルのリダイレクトなど）でソースを直接書き換えない。

- Neovim を通すと、Shift-JIS（cp932）や CRLF、最後の改行の有無を、元のファイルのまま書き戻す
- 目印をコマンドが付けるので、付け忘れて消せない行が残ることがない

## コマンド

調べているリポジトリのルートで実行する（ファイルのパスはそこからの相対パス）。
`list` と `clear` は、作業ディレクトリから上にたどって GTAGS・`.svn`・`.git` の
あるフォルダの下を探し、どれも無い所では `error: not in a project` で止まる:

```bash
nvim --headless "+lua require('taka.debug_lines').cli{'add', 'src/a.c', '120', 'path-B'}" +qa
nvim --headless "+lua require('taka.debug_lines').cli{'list'}" +qa
nvim --headless "+lua require('taka.debug_lines').cli{'clear', 'path-B'}" +qa
```

| 形 | すること |
|---|---|
| `'add', FILE, LINE[, GROUP]` | LINE 行目の**下**に入れる（0 ならファイルの先頭）。入れた行と、その上の行を表示する |
| `'list'[, GROUP]` | デバッグ行の一覧。1 行が `ファイル:行: [印] 本文` で、印は AI の行が `[AI p]`、利用者の行が `[p]`、グループ無しが `[-]`（AI なら `[AI -]`）。番号は本文の目印の `#7`。利用者の行も出る。読むのは、デバッグ行を入れたと覚えているファイルだけ（`add` したファイルと、利用者が Neovim で入れたファイルは覚えている） |
| `'clear'[, GROUP]` | **AI が入れた行だけ**を消す。利用者の行（`DBG`）は消せないし、消さない |

- 入れる中身は環境変数 `DEBUG_LINE_TEXT` で渡す（本当の改行で複数行。各行に目印が付き、内側の字下げは保たれる。
  文字の `\n` は C の文字列の中のまま残る）。
  無ければその言語の最初のひな形（C は `fprintf(stderr, "[DBG-AI 7 group] %s:%d\n", __FILE__, __LINE__);`）
- 中身の `{tag}` は `DBG-AI 番号 グループ` に、`{n}` は番号に、`{where}` は `ファイル名:行番号` になる。
  **出力には必ず `[{tag}]` を入れる。** 実行ログのその文字から、番号でどの行かが一つに決まる
- 失敗すると `error: 理由` を出して終了コード 1 で終わる（行番号がファイルに無い、など）
- ほかのエディタ（利用者の Neovim など）が、そのファイルを**保存していない変更つきで**開いて
  いると、`add` は書かずに `error: ... changes not written in another editor` で止まり、
  `clear` はそのファイルを飛ばして `not taken out of ...` と出す。書くと、そちらで保存した
  ときにデバッグ行が消えるか、ファイルが食い違うため。利用者に、そちらで保存してもらってから
  やり直す。変更の無い状態で開いているだけなら、そのまま書ける

中身を渡す例（Git Bash）:

```bash
DEBUG_LINE_TEXT='fprintf(stderr, "[{tag}] len=%d\n", (int)len);' \
  nvim --headless "+lua require('taka.debug_lines').cli{'add', 'ssl/d1_srtp.c', '60', 'srtp'}" +qa
```

## 進め方

1. **入れる前にファイルを読んで、行番号を確かめる。** `add` は「その行の下」に入れる。
   `if` の条件の途中、`else` の直前など、文が切れる場所に入れない。`\` で続くマクロの
   中は入れてよい（`\` で終わる行の下に入れた行には、最後に `\` が付き、目印はその前に入る）
2. 調べごとに 1 つのグループ名を付ける（英数字と `_ . -`。例: `srtp-len`）。後でまとめて消せる
3. `add` の表示で、入った位置と字下げを確かめる
4. 利用者にビルドと実行を頼み、出力の `[DBG-AI グループ]` からどの行を通ったかを読む
5. 確かめ終わったら `clear グループ` で消し、`list` で残っていないことを確かめる。
   消してよいか分からないときは、消さずに残し、`<leader>dl` で一覧できると伝える

## ログを渡されたとき

利用者が実行のログやコンソールの出力を貼ったら、出力そのものを読むだけで終わらせず、
デバッグ行と突き合わせてから答える。自分が入れた行でも、利用者が入れた行でも同じ。

1. ログから `[DBG ...]` / `[DBG-AI ...]` の行を拾う。`DBG` の次の数字が番号で、その後ろの語が
   グループ（`[DBG 3 path-A]` はグループ `path-A`、番号 3。`[DBG 3]` はグループ無し）。
   番号が先になる前に入れた行は、`[DBG path-A 3]` のように最後が番号
2. 番号ごとに、ソースの行を突き合わせる。`list` の目印の `#番号` で探し、`list` に無ければ、
   ログの角かっこを含めた文字（`[DBG 3 path-A]`）でリポジトリを検索する（その文字はソースにも
   そのまま書いてあるので、行がずれていても一つに決まる）。番号の無い `[DBG]` だけの行は、
   同じ文字の行が何か所にもありうるので、前後の出力や `__FILE__:__LINE__` で絞る
3. ログに出た順に、ファイルと行と、その行が何をする所かを並べる。同じ番号が何度も出たら
   回数を数える（ループや呼び出しの回数）。グループの中で**出なかった番号**は、通らなかった
   場所なので、それも挙げる
4. 「どこまで通り、どこから先へ行かなかったか」を言い、その分かれ目の条件をソースで確かめる。
   道筋の説明が長くなるなら、`nvim-trace` のスキルでトレースに書く
5. 確かめるのに足りなければ、足りない所にデバッグ行を足して、もう一度の実行を頼む

ログの行番号（`__LINE__` の出力）は、ビルドしたときの行で、その後にソースが変わっていると
ずれる。ずれていても、番号での突き合わせは正しい。

## 決まり

- 利用者の行（`DBG`、`-AI` の付かない目印）は、書き換えも消しもしない
- 目印の付いた行を、手で書き換えない。直すときは `clear` してから入れ直す
- 調べ終わってもデバッグ行が残るときは、そのことと件数をチャットで伝える
